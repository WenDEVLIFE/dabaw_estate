## Architecture and conventions

- **Routing:** Next.js App Router. Pages live in the repo-root `app/` directory (NOT `src/app/`).
- **Current state:** greenfield starter — only `app/layout.tsx`, `app/page.tsx`, `app/globals.css`, `app/favicon.ico`.
- **Path alias:** `@/*` → project root (`./*`) per `tsconfig.json`.
- **Styling model:** Tailwind v4 `@import "tailwindcss"` + `@theme inline` tokens in `app/globals.css`.
- **Next config (`next.config.ts`):** `cacheComponents: true`, `partialPrefetching: true`, `experimental.agentFeedback: true`, Turbopack rule mapping `*.css` to the Tailwind loader.
- **Data model:** static TypeScript/JSON mock records (planned `src/data/properties.ts`); React state for interactivity; `localStorage` optional for favorites only.
- **Component plan (guide, not mandate):** `components/layout`, `components/properties`, `components/ui`, `lib/utils.ts`, `types/property.ts` (see `docs/project.md` §15).
- **Planned routes:** `/`, `/properties`, `/properties/[slug]`, `/buy`, `/rent`, `/commercial`, `/short-stays`, `/contact`, `/admin`.

## Hard constraints (non-negotiable)

- NO database, backend, server actions, APIs, real authentication, or payment integrations.
- NO API keys, DB credentials, or backend environment variables.
- All data is local mock/sample content; all inquiry submission and admin CRUD are client-side simulations that must be clearly labeled as demos.
- Must build and deploy as a static/frontend-only Next.js app on Vercel.
